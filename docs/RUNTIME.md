# 更新規則・計算・評価の仕様

## 実行API

自作コードは `step` 関数を定義します。初期状態が必要な場合は `init` を定義します。次の表の座標、目的関数、学習率はこのシミュレーションでは無次元（SI単位1）です。物理単位を持つ問題にそのまま転用する前提ではありません。

| 名前 | 日本語の意味 | 定義／範囲・前提 | 単位 | 型 |
|---|---|---|---|---|
| `a` | ランナーから渡す入力 | 各更新の開始時に新規作成 | 該当なし | オブジェクト |
| `a.point` | 更新前の位置 | 2要素。両方とも地形の表示・評価範囲内 | 1 | 実数ベクトル |
| `a.state` | 前回から保持する内部状態 | `init` の返値、または前の `step` が返した `state` | 内容による | 任意の対応値 |
| `a.params.lr` | 学習率 | 正、100以下 | 1 | スカラー |
| `a.params.beta` | 一次履歴係数 | 0以上1未満 | 1 | スカラー |
| `a.params.beta2` | 二次履歴係数 | 0以上1未満 | 1 | スカラー |
| `a.params.eps` | 安定化定数 | 正、有限。UI既定値0.00000001 | 1 | スカラー |
| `a.params.wd` | 重み減衰係数 | 非負、有限 | 1 | スカラー |
| `a.t` | 更新番号 | 初回更新1。`init` では0 | 1 | 整数 |
| `a.bounds` | 座標の下限と上限 | 両軸で共通。範囲外の評価・移動は停止 | 1 | 長さ2の配列 |
| `a.loss(point)` | 目的関数評価 | 1呼出しを評価1コールとして課金 | 1 | 関数から実数 |
| `a.grad(point)` | 解析勾配の評価 | 1呼出しを評価1コールとして課金 | 1 | 関数から実数ベクトル |
| `a.random()` | 決定的な疑似乱数 | seedで初期化、0以上1未満 | 1 | 関数から実数 |
| 戻り値 `point` | 次の位置 | 必須、有限数2個 | 1 | 実数ベクトル |
| 戻り値 `state` | 次回の状態 | 省略時は現在の状態を保持 | 内容による | 任意の対応値 |
| 戻り値 `metrics` | 観測したい内部値 | 最大12項目。ベクトルは先頭4成分を展開 | 内容による | 名前と数値の対応 |
| 戻り値 `points` | 補助的な候補点 | 描画のみ、最大64点。評価したことの証明にはならない | 1 | 2次元点の配列 |
| 戻り値 `done` | 手法自身による終了 | trueで終了。目標達成と同義ではない | 1 | 真偽値 |

### 最小例

以下の `g` は現在の勾配ベクトル、`v` は現在位置の各成分、`i` は成分の添字（0または1）です。すべて無次元で、位置から学習率と勾配の積を引く項の単位・形状が一致します。

```js
function step(a) {
  const g = a.grad(a.point);
  return {
    point: a.point.map((v, i) => v - a.params.lr * g[i]),
    metrics: { gradient: g }
  };
}
```

`a.grad` を呼ばず、`a.loss` と `a.random` だけを使う手法にも対応します。1更新内の複数点探索や複数回の勾配評価が可能です。状態の数は2本に固定していません。配列の配列で行列の計算も記述できますが、タスクの位置ベクトル自体は2次元です。

## 対応構文

関数宣言、関数式、矢印関数、変数宣言、if、条件式、for、while、do...while、for...of、break、continue、return、通常のtry/catch、配列・オブジェクト、分割代入、算術・比較・論理演算を扱います。定義した更新規則以外に演算数や状態数を数学的に固定しません。

対応する配列メソッドは map、reduce、forEach、filter、some、every、slice、fill、push、pop、shift、unshift、reverse、concat、join、includes、indexOfです。Mathの基本的な数値関数を提供します。乱数は `Math.random` ではなく `a.random` を使います。

これは完全なECMAScript実装ではありません。import、class、async、generator、Promise、DOM、fetch、WebSocket、eval、Function、Date、this、プロトタイプ操作、正規表現、BigInt、任意の外部ライブラリを提供しません。`var` の巻き上げ、for-letで各反復ごとに捕捉される閉包、疎配列の穴など、一部のJavaScript細部とは異なります。数値配列と純粋な更新関数を基本として記述してください。

## 制限

1実行に対して、AST訪問／関数呼出し200万、累積の配列・データ要素20万、配列長1万、再帰64段、コード2万文字、文字列2万文字を上限とします。AST訪問数はCPU命令数やFLOPsではありません。累積要素数はライブメモリのバイト数ではありません。

更新回数は最大2,000、目的関数と勾配の合計コールは最大20,000です。Workerの実時間には別途停止タイマーがあり、ジョブ数によって9〜28秒、設定上限45秒です。低速端末では命令予算に到達する前に実時間で停止する可能性があります。親画面の「停止」でもWorkerを終了できます。

## 地形と微分

`x`、`y` は2つの無次元座標です。数式は700文字まで。関数はsin、cos、tan、tanh、exp、log、sqrt、abs、min、max、powに対応します。勾配は双対数による前向き自動微分で計算します。手描きブラシはガウス形状を加算し、同じ関数の解析勾配を加えます。

`abs` のゼロでは勾配0、`min/max` の同値では先の引数の微分、`sqrt` のゼロでは便宜上0を採用しています。これらの点で通常の微分が存在することを主張しません。`log` の非正入力や、微分が非有限になる式はエラーになります。実行域外の点を勝手に切り詰めません。グリッドの描画解像度は136×136で、実際の評価点はそのグリッドへの丸めを行いません。

## 履歴と表示

各履歴行は更新後の位置と損失を持ち、勾配はその更新の直前の位置で取得した診断値です。勾配矢印と更新矢印も更新前の位置から描画します。描画する矢印は視認性のため長さを正規化しており、画面上の長さを物理的な大きさと解釈しないでください。

診断用の勾配計算は別に数え、オプティマイザへ渡しません。計算時間にはランナーの解析・診断コストも含まれますが、Canvas描画は含みません。再生速度は履歴を変えません。CPUとブラウザが異なる測定時間を公式順位として扱いません。

## スコア

未編集で最適値が既知のプリセットだけを採点します。初期の最適値との差から最終位置の差までの対数改善率に最大800点、目標到達した実行に限り未使用の評価予算割合に最大200点を与えます。初期点がすでに目標内なら0点、エラー・実行制限・範囲外終了も0点です。手描き／数式編集の地形は最適値が未知なのでスコアを付けません。

目的関数1回と勾配1回は同じ1コールとして数える便宜的な指標で、実コストが等しいという主張ではありません。開始点、各更新後の記録用目的関数評価も予算に含めます。候補を探査しただけの最良値と、実際に返した最終位置の損失は区別します。

共通チャレンジ `suite-v1` はボウル・細長い谷・曲がった谷の各3開始点、300更新、1,200評価コール、seed 1/2/3、地形ごとの学習率を固定します。その他はbeta 0.9、beta2 0.999、eps 0.00000001、wd 0.01です。9ケースを同じ重みで平均します。コードが設定値を無視することや公開課題へ過適合することは防ぎません。共有結果は自己申告であり、正式な競技の不正防止機構ではありません。
