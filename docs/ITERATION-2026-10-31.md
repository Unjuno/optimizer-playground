# v0.4.0 — 2つの分析画面を行き来する

**2026-10-31 / browser CPU prototype / デプロイ前の開発版**

## この変更の意図

「地形上で何が起きたか」と「各時刻に勾配・移動平均・実更新がどう変わったか」を往復できるようにする。初心者でも驚いた軌跡上の一点を直接選び、同じ更新番号の内部信号まで確認できることを優先した。

## 追加した機能

- 地形ツールバーの **「軌跡を調べる」** を選択すると、記録済み経路全体のガイド線が現れる。線の途中も含めクリック／タップで最も近い手法・更新時刻に移動する。遠い位置では設定・開始点を変えない。
- 損失チャートに加えて、右側の**勾配・移動平均・更新量の時系列チャート**からも更新番号を選択できる。キーボードの左右矢印も対応。
- 更新番号とx/y成分に応じて、出発点の勾配・内部状態として公開された移動平均・実際の移動量を数値表示する。移動平均が存在しない手法は「—」になる。
- **勾配の時刻と位置の曖昧さを解消**した。既存の `history[t].gradient` は「更新を開始した点の勾配」のまま保持し、`history[t].gradientAtPoint` に「更新後に表示される点の勾配」を追加。現在位置の勾配ノルムは後者から計算する。
- CSVに `departure_gradient_x/y` と `point_gradient_x/y` を別カラムで出力。値が記録されていない旧共有データは空欄にし、値を作り出さない。

## 変更しない機能

- 最適化アルゴリズム本体、スコア式、固定9課題、関数・勾配評価予算、パラメータ上限。
- 起動時の自動実行禁止、ログイン不要、投稿前は自動送信しないこと、共有コードを自動実行しないこと。
- 2変数・CPU/JavaScript Number(FP64) の実行境界。Python/CUDAの実行や実際のニューラルネット学習は未実装。

## 科学的な意味・誤解しやすい点

「出発点の勾配」は、その点の解析勾配の診断値である。任意のオプティマイザが必ずその勾配を内部で使ったという意味ではない。勾配なしのアルゴリズム、複数点で評価するアルゴリズム、独自の変換を加えるアルゴリズムにも、この区別を適用する。

「移動平均」はコード側が `metrics.m` として返す場合にのみ表示する。非公開の状態を推測して描画しない。

## 実行条件・検証

- Linuxコンテナ / Node.js 22.16.0 / Headless Chromium（CPU） / Python Playwright。
- `npm run check:browser` : Node単体48/48、Chromium既存の27項目、失敗比較1項目、連動検査1シナリオ PASS。
- `tests/inspection.test.mjs`: 選択範囲、重なる手法、範囲外・無効値、長い線分の中点。
- `tests/core.test.mjs`: 2次元二次関数で出発点／到着点の解析勾配を比較。
- `tests/browser-inspection.py`: 地形・信号チャート・CSV・スマートフォン表示・既存の開始点編集の回帰。
- 共有APIはNode HTTPテストあり。公開HTTPS・実HTTPブラウザ投稿→共有→削除は未検証。

**H:** 同じ記録の同じ更新を空間上と時系列上で選択すると、出発点勾配・現在点勾配・更新量が記録と一致する。
**T:** 固定二次関数、SGD学習率0.3、初期点(2,1)、上限20更新、1手法、Chromium CSSピクセルを用い、境界・モバイルも確認。各機能1例以上、失敗時に停止。
**D:** すべての選択・数値・計算結果が期待と一致し、全自動テストが通過したらPASS。公開HTTPはUNCERTAIN。
**C:** 別ブラウザ、タッチ端末、非線形地形で近接点が重なる場合は、ヒットテストで別のステップが優先される可能性がある。
**U:** 座標クリックの許容半径はCSSピクセルで18（タッチ26）。これは統計測定ではない。数値計算はIEEE 754 FP64であり、合成標準不確かさ・包含係数の測定は行っていない。
